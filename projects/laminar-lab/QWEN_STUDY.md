# Qwen LoRA：先查奖励有没有信号，再讨论策略陈旧度

这是 Laminar-Lab 的语言模型实验。实时异步、故障和 Adam 恢复见 [Live Study](live-study.html)；这些机制**没有**接入本页的 Qwen 实验。

## 问题与对照

- 在本地 Apple GPU 读取固定版本 `mlx-community/Qwen3-4B-Instruct-2507-4bit`（`50d427756c6b1b2fe0c0a10f67fbda1fc8e82c1b`）；量化基座冻结，只更新最后两层 q/v 投影的 rank-4 LoRA（81,920 参数）。语言模型在末位置给出真实词表 logits，但决策只允许单 token A/B，属于 contextual bandit，不是开放式多步推理训练。
- 任务：对比两列数的和。每题八次独立给定策略的随机抽样；奖励为答对得 1、否则 0。三个种子各比较 lag 0 / 2，共用样本顺序和随机数，不强制动作一致。每链 12 批次，每批两步 Adam。裁剪旧行为概率比、冻结参考策略 KL 均作用于二动作分布；温度 2。
- 训练 96 题，留出 64 题，另外 64 道更长、取值更大的迁移题；无完全相同或 A/B 对调后的相同输入。两批共用同一任务和评估集，不能当成独立重复验证。确定性求和 128/128，本任务不需要语言模型。

## 失败和追加实验

初始协议 576 个组中只有 **5** 个组的奖励有差异。六条链最终在两套评估中均只选 A，均为 32/64。零方差组的组内相对优势为零；KL/Adam 的数值变化与适配器哈希变化不是任务学会的证据。

追加对照：只用训练输入（无标签）的冻结模型 logit 差中位数，减去 A 的全局偏置；该修正属于部署策略的一部分。LLM 前向到最后位置直接做语言头投影，训练集和评估集与第一批相同。获得 **545/576** 个有区分度的奖励组，后续每次优化都有可测梯度。校准本身把固定留出从 32/64 提到 40/64，不能把它计入 RL 收益。

| 种子 | lag 0 留出 / 迁移 | lag 2 留出 / 迁移 |
|---|---|---|
| 7 | 43/64 · 35/64 | 41/64 · 36/64 |
| 19 | 32/64 · 32/64 | 41/64 · 34/64 |
| 41 | 32/64 · 32/64 | 40/64 · 36/64 |

校准冻结基线为 40/64 和 35/64。lag 2 三组的单步峰值裁剪比例较高，但准确率差异方向混合。种子 19、lag 0 留出全选 B，留出负对数似然由 0.686 变为 0.837；这比单看准确率更直接地揭示了偏置反转。三种子共享评估题，不给显著性或普适结论；偏差校准之后的实验不是预注册，不能据此做生产准入保证。

## 可复查证据

- 两批 12 条真实优化链，144 个采样批次、288 次 Adam 更新、9,216 条动作抽样。抽样记录可从带版本的行为概率和均匀随机数复算；逐条复算奖励、版本链接、预测标签、准确率和 NLL。CPU 核验不声称能重建 GPU 梯度或证实来源真实性。
- 本机把校准版 6 份最终 adapter 重新载入同一固定基座；重新计算 768 组二动作概率（128 题 × 6 条链），与发布记录完全相同。只验证最终推断可恢复，不等于优化器崩溃恢复。原版与追加版保留分开的执行脚本指纹。公开仓库不分发基座或 adapter 权重；运行器可生成 adapter。
- 对外展示的判断：**先看有信号的奖励组比例、动作分布和校准损失，再看 lag 和 clipping**。如果奖励已经饱和，提高吞吐不会增加有学习信号的数据。

## 复现

Python 3.11，MLX 0.32.4 / mlx-lm 0.31.3。已有本地固定版本 safetensors 时，进入本项目目录并运行：

```bash
python -m laminar_lab.llm_policy --model "$PINNED_MODEL" --center --output /tmp/qwen-repro --weights /tmp/qwen-adapters
python -m laminar_lab.qwen_reload --model "$PINNED_MODEL" --runs /tmp/qwen-repro --adapters /tmp/qwen-adapters --output /tmp/qwen-reload.json
python -m laminar_lab.qwen_audit --artifacts artifacts
```

未校准首次批次的原始运行器在 `artifacts/qwen-policy/runner-original.py`。本版本 GPU 训练的首次批次与追加批次数据相同，源代码快照不同；后者只改中心化及语言头位置选择。原始结果以 `artifacts/qwen-policy/`、`artifacts/qwen-centered/` 和 `artifacts/qwen-reload.json` 为准。无 API、真实业务数据、工具操作或多机 GPU 吞吐结论。
