# 产品问题与验收边界

## 目标用户（假设，未做访谈）

搭建 AI/Agent 工作流的个人开发者或小团队，需要判断“错误发生在哪、该不该重试、重跑是否重复提交、恢复是否真正复用完成结果”。这是待真实访谈确认的价值假设，不是已验证市场需求。

## 一个任务闭环

选择故障负载与资源限制 → 运行同清单对照 → 查看成功率与尾延迟 → 选择失败任务 → 追踪异常/重试/检查点 → 导出原始结果 → 修改配置再复核。

## 主要功能与可观察验收

|需求|实现|验收证据|
|---|---|---|
|不要为看 Demo 安装模型|标准库运行 + 单文件离线展示|无需网络/密钥查看参考实测|
|对照不能换一套故障|seed 散列固定任务节点故障|同重复的 manifest_hash 相同|
|失败要定位到节点和尝试|事件 time/stage/task/attempt/status|界面选任务查看轨迹|
|重试要有停止条件|错误分类、次数、整体预算|永久错误不重试；预算取消|
|恢复不能重复有副作用操作|本地 SQLite 幂等与检查点|应答丢失对照、跨进程恢复测试|
|数字不能凭空生成|原始 JSON 导出 + checksums|报告由实测汇总生成|

## 非目标

不提供通用 DAG 编辑器、外部模型 API 接入、商用用户账号、公网服务、生产监控、分布式事务或自动学习调度算法。不把按钮数量或中间件数量当作产品深度。

## 异常交互

- 离线点击运行：说明需要本机后端，不伪造执行成功。
- 静态 Pages 点击运行：缺少 API 时提示限制。
- 无效配置：服务返回清晰错误，按钮恢复可操作。
- 同时请求对照：服务返回 429，避免无界占用资源。
- 导入数据：标注用户来源未核验，使用 textContent 展示，限制尺寸和结构。
