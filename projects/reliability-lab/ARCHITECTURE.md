# 架构与工程决策

## 数据流

提交 N 个工作流 → 有界信号量 → ingest → retrieve → analyze → validate → commit。
每个节点 → 超时保护 → 异常分类 → 有限指数退避 → 成功输出写检查点。
commit → SQLite 幂等账本 → 模拟应答丢失 → 重试复用提交结果。
每个事件 → 单调时钟、顺序编号、节点、任务、尝试号 → 原始 JSON → 统计与交互展示。

## 模块

- config.py：参数校验、确定性故障清单、配置签名。
- engine.py：asyncio 执行器、Worker 协议、重试/预算/取消、事件与统计。
- store.py：SQLite 成功节点检查点、作用域契约、提交账本。
- cli.py：运行、对照、评测、持久恢复、环境与哈希导出。
- server.py：仅本机 HTTP API，固定路由、同源校验、请求大小和实验并发限制。
- retrieval.py：实际本地 BM25 和词项重叠基线、12 篇自建文档、20 问题及困难改写组；无词项证据时拒绝产生答案。
- crash_child.py：仅在受控实验子进程的持久边界 os._exit；不操作其他应用。
- advanced.py：检索实验、3 个崩溃探针、27 次并发/超时扫描与原始证据。
- demo.html：单文件展示，默认内联本机实测；可导入 JSON、追踪事件，不依赖外部 JS。

## 关键取舍

1. **标准库优先**：零下载即可复现。没有引入 Ray，因为本机异步等待不需要分布式资源调度，也无法在当前硬件证明 GPU 集群效果。
2. **固定 DAG**：聚焦失败和恢复，不做通用工作流编辑器。并发受信号量控制，预算从提交起包含排队；流量过大时后排任务可能预算耗尽，这不是隐藏异常。
3. **错误分类**：暂时性错误和单次超时可重试；永久错误和结构校验拒绝终止。单次尝试超时耗尽与工作流预算耗尽分别统计。
4. **幂等局限**：SQLite effects 表中 (scope,task) 唯一；提交和 ledger 写入为同一事务。只保护同一数据库中的 side effect，不能保护任意外部接口。
5. **检查点契约**：保存成功输出，绑定配置散列、版本、策略、执行器身份及运行时核心代码散列。更换执行器或代码拒绝复用旧输出。检索执行器绑定文档/问题及自身代码散列。故障只注入首次尝试；跨进程恢复未完成节点会重新从第一次尝试注入，故障不自动“消失”。
6. **同步数据库写入**：本机小样本 SQLite 在 event loop 上同步提交，可能影响尾延迟；因此不声称适合大规模生产或高吞吐服务。
7. **指标透明**：全部请求 P95 和成功请求 P95 分开；吞吐分全部完成与成功完成。没有把失败早退带来的快速完成描述为性能提升。
8. **公平性**：每个策略使用同 seed 和同故障清单；慢操作固定 140ms，不随超时参数改变。真实计时与多次重复仍只产生描述性实验，未建立生产外推。
9. **取消语义**：asyncio.wait_for 取消合成 sleep，finally 释放资源。Worker 协议要求取消友好；阻塞 I/O、C 扩展或忽略取消的插件不在验证范围。
10. **本机服务安全**：环回监听、Host/Origin 校验、JSON 类型、8192 字节上限、交互 count 上限 48、一次只运行一个对照、没有任意路径/命令/API URL 输入。不是公网安全服务。

## 下一阶段（未实现）

- 真实模型适配器：需要用户自有可使用的接口、预算、数据与授权；必须独立报告真实和合成实验。
- 外部副作用：以服务端幂等键和 outbox 合同验证，不能仅凭本地 ledger 保证。
- 大规模负载：加入 CPU 计算任务、进程池、队列背压和外部持久队列；先建立性能瓶颈再扩展。
- 更深故障实验：当前已验证持久边界子进程强制退出；尚未覆盖写事务中断、主机断电、磁盘故障或网络分区。
