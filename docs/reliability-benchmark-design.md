## 实验问题

在相同合成故障清单与并发上限下，单次执行、有限重试、带持久检查点及幂等提交的执行策略，如何影响：

- 工作流成功率与失败类型；
- 全部请求延迟和仅成功请求延迟；
- 重试放大、任务超时与工作流预算耗尽；
- 已写入但应答丢失的副作用重复；
- 恢复时已完成节点的重复计算。

## 实现范围

Python 标准库、本机异步 I/O 合成负载、固定 DAG、SQLite 持久化、离线报告、单文件静态展示、本机 API。没有 GPU、远程模型、训练、真实 API 计费、生产集群或公司内部数据。

不得把合成任务吞吐称为 token/s，也不得把本机测量推广为业务降本或生产可靠性。

## 验收清单

- 每次实验留存完整配置、负载签名、原始事件、逐任务结果和汇总。
- 同一 seed/工作流/节点的故障与策略无关；重试不会改变首次故障清单。
- 永久错误和输出校验错误不会因重试伪装成功。
- 超时取消后没有未被回收的实验子任务。
- 幂等提交只在本项目 SQLite ledger 范围内有效，不宣称分布式 exactly-once。
- 检查点复用绑定 seed、负载、实现版本和任务身份，配置不匹配拒绝恢复。
- 数据导入展示只用 textContent，不把用户 JSON 当 HTML 或脚本。
- AI 辅助实现如实标注；用户亲自理解和复核前，不宣称独立研发经历。
