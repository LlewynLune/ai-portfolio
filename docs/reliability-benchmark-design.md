# 可靠性实验台：方法依据与范围

本页说明本地可靠性实验的方法与验收范围，不作为招聘评分或履历证据。

## 机制依据

Ray官方任务容错文档区分应用级错误与系统级失败，支持选择重试异常、重试上限和任务取消。本项目独立实现“只重试可恢复错误”的本地教学版本，不使用Ray，不声称兼容其调度语义。来源：https://docs.ray.io/en/latest/ray-core/fault_tolerance/tasks.html

## 实验问题

在相同合成故障清单与并发上限下，单次执行、有限重试、带持久检查点及幂等提交的执行策略如何影响工作流成功率、失败类型、全部/成功请求延迟、重试放大、预算耗尽、副作用重复与节点重算。

## 范围

Python标准库、本机异步I/O合成负载、固定DAG、SQLite持久化、离线报告、静态展示与本机API。没有GPU、远程模型训练、真实API计费、生产集群或内部数据。合成吞吐不称token/s，本机测量不外推业务降本。

## 验收

- 留存配置、负载签名、原始事件、逐任务结果与汇总。
- 相同seed/工作流/节点故障与策略无关，重试不改变首次故障清单。
- 永久错误/校验错误不得通过重试伪装成功。
- 超时取消后实验任务被回收。
- 幂等只在本地SQLite ledger范围有效，不宣称分布式exactly-once。
- 检查点绑定seed、负载、版本与任务身份，配置不匹配拒绝恢复。
- 导入JSON只作为数据，不当HTML或脚本执行。
- AI辅助实现与个人独立贡献分开记录。
